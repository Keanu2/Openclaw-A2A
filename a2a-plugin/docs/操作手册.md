# Openclaw-A2A 操作手册

> **文档位置**：`docs/操作手册.md`（由原根目录长 README 迁入）  
> **版本**：`1.4.3` · 插件 ID：`a2a-gateway`  
> **简介**：见根目录 [README.md](../README.md)

本手册按「一步一步照着做」编写。每一节都写清：**做什么 → 敲什么命令 → 看到什么算成功 → 失败怎么办**。

> 插件目录示例：`D:\openclaw\Openclaw-A2A`  
> 若你的路径不同，全文把该路径换成自己的即可。

---

## 先选一条路线

| 你的情况 | 做哪些章节 |
|----------|------------|
| 第一次接触，先确认代码能跑 | **第 0 章 → 第 1 章 → 第 2 章** |
| 两台机器在同一局域网 / Tailscale，能互相 ping 通 | **第 0 章 → 第 1 章 → 第 3 章** |
| 两台机器都在 NAT 后面，不能直连（最常见跨网需求） | **第 0 章 → 第 1 章 → 第 2 章 → 第 4 章 → 第 5 章** |
| 跨 NAT，且想用注册中心自动发现对端（少写死 peers） | **第 5 章做完 → 第 5A 章** |
| 以前用过独立 `tunnel-client`，要迁到本插件 | **第 6 章** |
| 要卸载插件 | **第 7 章** |

## 第 0 章：检查环境（约 5 分钟）

### 步骤 0.1 — 检查 Node.js

打开终端（PowerShell / CMD / bash），执行：

```bash
node -v
```

**成功：** 显示 `v22.x.x` 或更高（例如 `v22.14.0`）。  
**失败：** 提示找不到命令 → 先安装 [Node.js 22+](https://nodejs.org/)，装完重开终端再查一次。

再查 npm：

```bash
npm -v
```

**成功：** 显示版本号（如 `10.x.x`）。

### 步骤 0.2 — 检查 OpenClaw

```bash
openclaw --version
```

或：

```bash
openclaw -h
```

**成功：** 能打印版本或帮助。  
**失败：** 先按 OpenClaw 官方文档安装，并保证 Gateway 能启动：

```bash
openclaw gateway status
```

若未运行，可先：

```bash
openclaw gateway start
```

（具体子命令以你安装的 OpenClaw 版本为准。）

### 步骤 0.3 — 检查本插件目录是否存在

```bash
# Windows PowerShell
dir D:\openclaw\Openclaw-A2A

# 或 Linux / macOS
ls /path/to/openclaw/Openclaw-A2A
```

**成功：** 能看到 `package.json`、`index.ts`、`src`、`README.md` 等。  
**失败：** 确认是否拷错目录；本手册只针对 **tunnel 集成版**，不是 `openclaw-a2a-gateway-lhy`。

### 步骤 0.4 —（仅 NAT 模式需要）检查 Python

```bash
python --version
# 若上面不行，试：
python3 --version
```

**成功：** Python 3.7+。后面第 4 章要用它跑中继。

## 第 1 章：安装插件到 OpenClaw（必做）

下面在 **每一台要跑 A2A 的电脑** 上都做一遍。

### 步骤 1.1 — 进入插件目录

```bash
cd D:\openclaw\Openclaw-A2A
```

### 步骤 1.2 — 安装 npm 依赖

```bash
npm install
```

**成功：** 命令结束无红色报错；目录下出现 `node_modules`（里面应有 `tsx`、`ws` 等）。  
**失败常见原因：**

- 网络不通 → 配置 npm 镜像后再装  
- Node 版本太低 → 升到 22+  
- 若曾用 `npm install --production` 只装了生产依赖 → 请改用普通的 `npm install`（测试需要 `tsx`）

若仍提示 `cannot find package 'tsx'`，单独补装：

```bash
npm install tsx
```

然后再跑 `npm run test:tunnel`。

### 步骤 1.3 —（强烈建议）先跑本地隧道测试

还没装进 OpenClaw 之前，先证明隧道代码本身没问题：

```bash
npm run test:tunnel
```

**成功：** 终端里测试用例都是 pass / ok，进程退出码为 0。

再跑冒烟：

```bash
npm run smoke:tunnel
```

**成功：** 最后一行出现：

```text
SMOKE OK
```

**若这里就失败：** 先不要装插件。把完整报错留下排查（缺依赖就再执行一次 `npm install`）。

### 步骤 1.4 — 若以前装过旧版 a2a-gateway，先卸掉

避免两个目录抢同一个插件 ID：

```bash
openclaw plugins list
```

若列表里已有 `a2a-gateway`，执行：

```bash
openclaw plugins uninstall a2a-gateway --dry-run
openclaw plugins uninstall a2a-gateway
```

按提示确认。需要跳过确认时：

```bash
openclaw plugins uninstall a2a-gateway --force
```

### 步骤 1.5 — 用本目录安装插件

```bash
openclaw plugins install D:\openclaw\Openclaw-A2A
```

路径务必是 **本集成版** 的绝对路径。

**成功：** 命令提示安装完成 / installed。  
**失败：** 检查路径是否存在、OpenClaw 是否有权限读该目录。

### 步骤 1.6 — 允许并启用插件

```bash
openclaw config set plugins.allow '["a2a-gateway"]'
openclaw config set plugins.entries.a2a-gateway.enabled true
```

说明：

- 插件 ID 是 `a2a-gateway`（不是文件夹名）  
- 若你还有其它插件要保留在 allow 列表里，把它们一起写进数组，例如：`'["telegram","a2a-gateway"]'`

### 步骤 1.7 —（可选）显式指定加载路径

部分环境下需要：

```bash
# Windows：注意 JSON 里反斜杠要写成 \\
openclaw config set plugins.load.paths '["D:\\openclaw\\Openclaw-A2A"]'
```

### 步骤 1.8 — 重启 Gateway

```bash
openclaw gateway restart
```

等几秒。

### 步骤 1.9 — 确认插件已加载

```bash
openclaw plugins list
```

**成功：** 能看到 `a2a-gateway`，且为启用 / enabled 状态。

也可用：

```bash
openclaw plugins inspect a2a-gateway
```

### 步骤 1.10 — 确认本机 A2A HTTP 已监听

在同一台机器上执行：

```bash
curl -s http://127.0.0.1:18800/.well-known/agent-card.json
```

若上面没有内容，再试：

```bash
curl -s http://127.0.0.1:18800/.well-known/agent.json
```

**成功：** 返回一段 JSON（里面有 `name`、`protocolVersion` 等字段）。  
**失败（连接被拒绝）：**

1. 再执行一次 `openclaw gateway restart`  
2. 看 Gateway / 插件日志里有没有 `a2a-gateway: HTTP listening`  
3. 确认没有别的程序占用 18800  
4. 确认插件确实 `enabled: true`

到这里，**插件已作为 OpenClaw 插件跑起来**，具备 A2A 能力（默认还是直连模式，未开 NAT 隧道）。

## 第 2 章：怎么改插件配置（后面都会用到）

插件配置挂在：

```text
plugins.entries.a2a-gateway.config
```

你可以用下面任意一种方式写入。

### 方式 A — 查当前配置

```bash
openclaw config get plugins.entries.a2a-gateway
```

或查看整份配置文件位置（常见在用户目录下的 OpenClaw 配置，具体以 `openclaw config` 帮助为准）。

### 方式 B — 用 `config set` 写入整段 JSON（适合一次写完）

把下面整段保存成文件，例如 `a2a-config.json`，再按你的 OpenClaw 版本用导入 / set 的方式写入。  
若 CLI 支持直接 set 对象，也可：

```bash
openclaw config set plugins.entries.a2a-gateway.config "<这里贴压缩后的 JSON>"
```

更稳妥的做法：**编辑 OpenClaw 的配置文件**，找到 `plugins.entries.a2a-gateway`，在其下增加或修改 `config` 字段。

### 方式 C — 手改配置文件（推荐新手）

1. 找到 OpenClaw 配置文件（常见名称类似 `openclaw.json` / `~/.openclaw/config.json`，以你机器为准）。  
2. 找到类似结构：

```json
{
  "plugins": {
    "entries": {
      "a2a-gateway": {
        "enabled": true,
        "config": {
        }
      }
    }
  }
}
```

3. 把第 3 / 4 / 5 章给出的 JSON **填进 `config` 里**。  
4. 保存文件。  
5. 执行：

```bash
openclaw gateway restart
```

**注意：** JSON 不能有注释；字符串用双引号；改完务必重启。

## 第 3 章：直连模式（两端网络能互通）

适用于：同一局域网、Tailscale、或双方有公网可达 IP。  
**不要**写 `tunnel`，**不要**写 `tunnelDeviceId`。

下面假设：

- 电脑 A IP：`192.168.1.10`  
- 电脑 B IP：`192.168.1.20`  
- 都已完成第 1 章安装  

请先自己换成真实 IP：

```bash
# Windows
ipconfig

# Linux / macOS
ip addr
# 或
ifconfig
```

### 步骤 3.1 — 在电脑 A 写入配置

把 `plugins.entries.a2a-gateway.config` 设为：

```json
{
  "server": { "host": "0.0.0.0", "port": 18800 },
  "agentCard": {
    "name": "电脑A-Gateway",
    "url": "http://192.168.1.10:18800",
    "skills": ["chat"]
  },
  "peers": [
    {
      "name": "电脑B",
      "agentCardUrl": "http://192.168.1.20:18800/.well-known/agent-card.json",
      "auth": { "type": "bearer", "token": "token-for-B" }
    }
  ],
  "security": {
    "inboundAuth": "bearer",
    "token": "token-for-A"
  }
}
```

说明：

- `security.token` = **别人访问我时**要用的令牌 → 这里是 `token-for-A`  
- peer 里的 `auth.token` = **我访问对方时**要用的令牌 → 必须等于对方的 `security.token`

### 步骤 3.2 — 在电脑 B 写入配置

```json
{
  "server": { "host": "0.0.0.0", "port": 18800 },
  "agentCard": {
    "name": "电脑B-Gateway",
    "url": "http://192.168.1.20:18800",
    "skills": ["chat"]
  },
  "peers": [
    {
      "name": "电脑A",
      "agentCardUrl": "http://192.168.1.10:18800/.well-known/agent-card.json",
      "auth": { "type": "bearer", "token": "token-for-A" }
    }
  ],
  "security": {
    "inboundAuth": "bearer",
    "token": "token-for-B"
  }
}
```

核对令牌：

| | 电脑 A | 电脑 B |
|--|--------|--------|
| 本机入站 token | `token-for-A` | `token-for-B` |
| 访问对方时带的 token | `token-for-B` | `token-for-A` |

### 步骤 3.3 — 两台都重启

在 A、B 上分别执行：

```bash
openclaw gateway restart
```

### 步骤 3.4 — 在 A 上测能否打开 B 的 Card

在电脑 A 上：

```bash
curl -s -H "Authorization: Bearer token-for-B" http://192.168.1.20:18800/.well-known/agent-card.json
```

（若对方 `inboundAuth` 为 `none`，可去掉 `-H` 那一段。）

**成功：** 返回 JSON。  
**失败：** 检查防火墙是否放行 18800、IP 是否写错、对方 Gateway 是否在跑。

### 步骤 3.5 — 发一条 A2A 消息（业务验证）

在 OpenClaw 里调用 gateway method（名称以你环境为准，常见为 `a2a.send`），peer 名用配置里的 `name`，例如在 A 上发给 `电脑B`。

发送**本地文件**时，不要把 base64 塞进 `a2a.send` 的 `--params`（大文件会触发系统 `E2BIG`）。改用：

```bash
openclaw gateway call a2a.send_local_file --timeout 300000 \
  --params '{"peer":"电脑B","path":"/storage/media/100/local/files/Docs/Desktop/photo.jpg"}'
```

对应 Agent 工具名：`a2a_send_local_file`。默认内联上限 **50MB**（`security.maxInlineFileSizeBytes`）。  

**文件名规则（现行）：**

1. 传输名 **始终** = 本地 `path` 的 basename（忽略参数里的 `name`，避免 Agent 编造 `file.jpg`）  
2. 线上 FilePart 字段顺序为 `{ name, mimeType, bytes }`（name 在前，避免大段 base64 导致丢名落成 `file.ext`）  
3. 对端按该文件名落到 `fileStorage.tempDir`（未配置则临时目录）；详见第 8 章 `fileStorage`  
4. 聊天侧须原样回报保存绝对路径，勿改写成旧的 `/data/local/tmp/a2a-files/`  

详见 [源码修改说明.md](./源码修改说明.md) §2–§3。

也可用 OpenClaw 提供的工具 / 控制面（若有「发送到 peer」的 UI，选 peer `电脑B`）。

**成功：** 对端有响应 / 任务完成，无超时。  
**失败：** 看两边日志；优先查鉴权 401 与网络连通。

直连模式到此结束。若你还需要跨 NAT，继续第 4、5 章。

## 第 4 章：部署云端中继（NAT 模式必做，只做一次）

中继跑在一台 **两边都能访问** 的机器上（云主机最合适）。  
代码在未改动的目录：`D:\openclaw\a2a-relay-2`（或你的拷贝路径）。

### 步骤 4.1 — 登录中继机器，进入目录

```bash
cd D:\openclaw\a2a-relay-2
```

### 步骤 4.2 — 安装 Python 依赖

```bash
pip install -r requirements.txt
# 或
pip3 install -r requirements.txt
```

**成功：** `aiohttp`、`websockets`、`loguru` 等安装完成。

### 步骤 4.3 — 启动中继

```bash
python relay-server.py --host 0.0.0.0 --port 8080 --http-port 8081
```

保持这个窗口不要关（或用 systemd / pm2 / nssm 做成服务）。

含义：

- `8080`：WebSocket（插件要连的地址）  
- `8081`：HTTP 管理口（health / list）

### 步骤 4.4 — 本机检查中继是否活着

在中继机器上：

```bash
curl -s http://127.0.0.1:8081/health
curl -s http://127.0.0.1:8081/list
```

**成功：** `/health` 有正常 JSON；`/list` 一开始可能是空设备列表。

### 步骤 4.5 — 从业务机器检查能否访问中继

在电脑 A、电脑 B 上分别执行（把 `中继公网IP` 换成真实 IP 或域名）：

```bash
curl -s http://中继公网IP:8081/health
```

**成功：** 能返回内容。  
**失败：**

1. 云厂商安全组 / 防火墙放行 **8080、8081**（或你改过的端口）  
2. 本机网络能否出网  
3. 若只打算用 WSS，后面用 Nginx 反代后再测 `https://域名/...`

### 步骤 4.6 — 记下插件要填的 relayUrl

| 场景 | `tunnel.relayUrl` 写法 |
|------|------------------------|
| 内网临时测试 | `ws://中继局域网IP:8080` |
| 公网明文（仅测试） | `ws://中继公网IP:8080` |
| 生产（推荐） | `wss://你的域名`（经 TLS 反代到 8080） |

**务必**用 `ws://` 或 `wss://` 开头，不能用 `http://`。

## 第 5 章：激活嵌入式 Tunnel（跨 NAT 重点）

前提：第 1 章装好插件，第 4 章中继已启动且两边都能访问。

下面两台设备命名：

- 设备 A：`office-a`  
- 设备 B：`home-b`  

令牌约定：

- A 的入站令牌：`token-office-a`  
- B 的入站令牌：`token-home-b`

### 步骤 5.1 — 在设备 A 写入完整配置

编辑 `plugins.entries.a2a-gateway.config` 为：

```json
{
  "server": { "host": "127.0.0.1", "port": 18800 },
  "agentCard": {
    "name": "办公室 Gateway",
    "skills": ["chat"]
  },
  "tunnel": {
    "enabled": true,
    "relayUrl": "ws://中继公网IP:8080",
    "deviceId": "office-a"
  },
  "peers": [
    {
      "name": "home-b",
      "tunnelDeviceId": "home-b",
      "agentCardUrl": "http://127.0.0.1:18800/.well-known/agent-card.json",
      "auth": {
        "type": "bearer",
        "token": "token-home-b"
      }
    }
  ],
  "security": {
    "inboundAuth": "bearer",
    "token": "token-office-a"
  }
}
```

把 `ws://中继公网IP:8080` 换成你在第 4.6 步记下的地址。

逐项核对：

1. `tunnel.enabled` 必须是 `true` ← **打开隧道的总开关**  
2. `tunnel.deviceId` 必须是 `office-a`（本机身份）  
3. peer 的 `tunnelDeviceId` 必须是对方的 id：`home-b`  
4. peer 的 `auth.token` 必须等于对方 `security.token`  
5. `agentCardUrl` 在隧道模式下 host 可写 `127.0.0.1`（真正路由靠 `tunnelDeviceId`）

### 步骤 5.2 — 在设备 B 写入完整配置

```json
{
  "server": { "host": "127.0.0.1", "port": 18800 },
  "agentCard": {
    "name": "家里 Gateway",
    "skills": ["chat"]
  },
  "tunnel": {
    "enabled": true,
    "relayUrl": "ws://中继公网IP:8080",
    "deviceId": "home-b"
  },
  "peers": [
    {
      "name": "office-a",
      "tunnelDeviceId": "office-a",
      "agentCardUrl": "http://127.0.0.1:18800/.well-known/agent-card.json",
      "auth": {
        "type": "bearer",
        "token": "token-office-a"
      }
    }
  ],
  "security": {
    "inboundAuth": "bearer",
    "token": "token-home-b"
  }
}
```

两边 `relayUrl` 必须指向 **同一中继**。  
两边 `deviceId` 不能相同。

### 步骤 5.3 — 对照表（抄到纸上核对）

| 项目 | 设备 A | 设备 B |
|------|--------|--------|
| `tunnel.enabled` | true | true |
| `tunnel.relayUrl` | 同一中继 | 同一中继 |
| `tunnel.deviceId` | `office-a` | `home-b` |
| peer 名字 | `home-b` | `office-a` |
| peer.`tunnelDeviceId` | `home-b` | `office-a` |
| 本机 `security.token` | `token-office-a` | `token-home-b` |
| 访问对方的 `auth.token` | `token-home-b` | `token-office-a` |

### 步骤 5.4 — 先重启设备 A，再重启设备 B

```bash
openclaw gateway restart
```

### 步骤 5.5 — 看日志，确认隧道已连上

打开 OpenClaw / Gateway 日志，搜索：

```text
a2a-tunnel: connected as
a2a-gateway: tunnel enabled
```

**设备 A 成功示例：**

```text
a2a-gateway: HTTP listening on 127.0.0.1:18800
a2a-tunnel: connected as office-a → ws://...
a2a-gateway: tunnel enabled deviceId=office-a relay=ws://...
```

**设备 B** 同理，应看到 `home-b`。

**若没有这些日志：**

1. 配置是否保存成功（`openclaw config get plugins.entries.a2a-gateway`）  
2. `tunnel.enabled` 是否真是 `true`（布尔，不是字符串 `"true"`）  
3. `relayUrl` 是否以 `ws://` / `wss://` 开头  
4. 中继是否仍在运行  
5. 本机能否访问中继 8080（防火墙）

### 步骤 5.6 — 在中继上确认两台都注册了

在中继机器：

```bash
curl -s http://127.0.0.1:8081/list
```

**成功：** 列表里同时有 `office-a` 和 `home-b`。  
**只有一台：** 另一台没连上，回到 5.5 查那台的日志。  
**一台都没有：** 两边都没连上中继，查 `relayUrl` 与网络安全组。

### 步骤 5.7 — 业务发送验证

1. 在设备 A 上，向 peer 名 **`home-b`** 发一条 `a2a.send`（或控制面等价操作）。  
2. 在设备 B 上，向 peer 名 **`office-a`** 回一条。

**成功：** 两边都能收到/完成，无长时间超时。  
**失败：**

| 现象 | 优先检查 |
|------|----------|
| 超时 | `/list` 是否两个都在；对端 `18800` 是否监听；`tunnelDeviceId` 是否写反 |
| 401 | 令牌是否按对照表互指 |
| Device xxx not found | 对端未注册或 id 拼写不一致 |

### 步骤 5.8 — 停掉旧的独立 tunnel-client（如果有）

隧道嵌入成功后，**不要再跑**：

```bash
node client.js --local-port 18801 ...
```

同时：

- 取消该进程的开机自启 / PM2 / 计划任务  
- peer 的 URL **不要**再指向 `18801`  

本插件不再需要本地代理端口。

## 第 5A 章：用注册中心自动发现对端（可选）

> 源码侧说明见 [源码修改说明.md](./源码修改说明.md) §5。

本章解决的问题：**少写死 `peers`**。  
通信管道不变——仍是第 5 章的隧道；注册中心只当「通讯录」。

现网示例（以你环境为准）：

| 组件 | 地址 |
|------|------|
| 注册中心 | `http://121.37.53.35:8000` |
| 隧道 | `ws://121.37.53.35:8001`（与第 5 章相同） |

### 步骤 5A.1 — 先确认隧道已通

按第 5 章把两端 `tunnel.enabled=true`、同一 `relayUrl`、各自 `deviceId` 配好，日志出现：

```text
a2a-tunnel: connected as <你的deviceId> → ws://...
```

**还没开注册中心时，可以继续用手写 `peers` 发消息。**

### 步骤 5A.2 — 探活注册中心

在**能访问中心的机器**上（设备侧更可靠）：

```bash
curl http://121.37.53.35:8000/api/warmup-status
```

**成功：** JSON 里 `ready` 为 true。  
**失败：** 先别开 `registry`；中心不可达时插件仍会启动，但发现为空。

### 步骤 5A.3 — 两端打开 `registry`

在 `plugins.entries.a2a-gateway.config` 里增加（PC 示例；Phone 把 ID 换成自己的）：

```json
"peers": [],
"registry": {
  "enabled": true,
  "baseUrl": "http://121.37.53.35:8000",
  "dataset": "openclaw_devices",
  "serviceId": "HW-PC1",
  "registerOnStart": true,
  "discoverIntervalMs": 15000,
  "mergeWithStatic": true,
  "defaultPeerAuth": {
    "type": "bearer",
    "token": "12345678"
  }
}
```

说明：

1. **`peers: []`** = 验收「发现-only」；若要混用，可保留部分静态 peers（同名时静态优先）。  
2. **`defaultPeerAuth`** = 发现出来的对端用什么令牌访问；`peers` 为空时几乎必填。  
3. **`serviceId`** 建议等于 `tunnel.deviceId`。

改完后重启 Gateway（设备上常用 `sh /data/local/tmp/start-openclaw.sh`）。

### 步骤 5A.4 — 看日志：注册 → 发现（插件自动做）

启动后插件**按这个顺序**干活：

1. 本机 HTTP `:18800` 起来  
2. 连隧道并 `REGISTER device_id`  
3. 向注册中心：创建/确认 dataset → **POST 注册本机 Agent Card**（含 `metadata.tunnelDeviceId`）  
4. 定时 **GET 服务列表**，把别人转成内部 peer  

期望日志关键字：

```text
a2a-registry: registered: {"dataset":"openclaw_devices","serviceId":"HW-PC1"}
a2a-registry: discovered peers: {"count":1,"names":["HW-Phone1"]}
```

### 步骤 5A.5 — 确认中心里有两台

```bash
curl "http://121.37.53.35:8000/api/datasets/openclaw_devices/services"
```

**成功：** 列表里同时有两端的 `id`（如 `HW-PC1`、`HW-Phone1`）。

#### 聊天 / Gateway：手动注册与查询

`dataset` 始终用配置里的 `registry.dataset`（默认 `openclaw_devices`），聊天不用再传命名空间。

| 入口 | 作用 |
|------|------|
| 聊天意图「注册到注册中心」→ 工具 `a2a_registry_register` | POST 本机 Agent Card |
| 聊天意图「查注册设备 / 谁已注册」→ 工具 `a2a_registry_list` | GET 列表（含本机与他人的 `serviceId`、`tunnelDeviceId`、AgentCard） |
| CLI | `openclaw gateway call a2a.registry.register` / `a2a.registry.list` |

```bash
openclaw gateway call a2a.registry.register --timeout 60000 --params '{}'
openclaw gateway call a2a.registry.list --timeout 60000 --params '{}'
```

查询结果里的 **serviceId** 可直接作为后续 `a2a.send` 的 `peer`（对端需已被发现；本机不会给自己发）。

### 步骤 5A.6 — 发一条远场文本

两端隧道都在线后（若出现 `Device xxx not found`，先等对端 `a2a-tunnel: connected`）：

```bash
openclaw gateway call a2a.send --timeout 300000 --params '{
  "peer":"HW-Phone1",
  "message":{"text":"ping registry farfield"}
}'
```

**成功：** 返回 JSON，`statusCode` 200，task 完成。  
此处的 `peer` 名来自**注册中心发现**，不是手写 peers。

### 步骤 5A.7 — 想回到纯手写配置

把 `registry.enabled` 设为 `false`（或删掉 `registry`），按第 5 章把 `peers` 写回去即可。

## 第 6 章：从旧「双进程」迁移（一步一步）

旧方式：

```bash
node client.js \

  --device-id device-a \
```

### 步骤 6.1 — 参数对照抄写

|--------|--------|

### 步骤 6.3 — 先迁一台

1. 按第 1 章安装本插件。  
2. 按第 5 章写好 `tunnel` + `peers`。  
3. `openclaw gateway restart`。  
4. 确认日志与中继 `/list` 里有本机 `deviceId`。  
5. 与仍使用旧 `tunnel-client` 的对端互发一条消息。  
6. 成功后再迁另一台，最后停掉所有旧 `client.js`。

## 第 8 章：配置字段速查

### `tunnel`（嵌入式 tunnel-client）

| 字段 | 必填 | 默认 | 说明 |
|------|------|------|------|
| `enabled` | 否 | `false` | `true` = 打开隧道 |
| `relayUrl` | enabled 时必填 | — | `ws://` 或 `wss://` |
| `deviceId` | enabled 时必填 | — | 本机在中继上的唯一 ID |
| `localServicePort` | 否 | `server.port` | 入站转到本机端口 |
| `heartbeatIntervalMs` | 否 | `15000` | 心跳 |
| `requestTimeoutMs` | 否 | `300000` | 单次转发超时 |
| `reconnectIntervalMs` | 否 | `5000` | 重连间隔 |
| `maxReconnectAttempts` | 否 | `10` | 最大重连次数 |

### `peers[]`

| 字段 | 说明 |
|------|------|
| `name` | 逻辑名，发消息时用这个名字 |
| `agentCardUrl` | Card 地址；隧道模式下主要用 path |
| `tunnelDeviceId` | 有则走中继；无则直连 |
| `auth.type` / `auth.token` | 访问该 peer 时的鉴权 |

### `registry`（云端通讯录，可选）

| 字段 | 必填 | 默认 | 说明 |
|------|------|------|------|
| `enabled` | 否 | `false` | `true` = 启动时注册 + 周期发现 |
| `baseUrl` | enabled 时必填 | — | 如 `http://121.37.53.35:8000` |
| `dataset` | 否 | `openclaw_devices` | 命名空间 |
| `serviceId` | 否 | `tunnel.deviceId` | 本机在中心的 ID |
| `registerOnStart` | 否 | `true` | 启动时 POST 本机 Card |
| `discoverIntervalMs` | 否 | `30000` | 发现周期（≥5000） |
| `mergeWithStatic` | 否 | `true` | 与静态 peers 合并；同名静态优先 |
| `defaultPeerAuth` | 建议 | — | 发现出的 peer 的鉴权（`peers` 为空时重要） |
| `authToken` | 否 | — | 调中心 HTTP 的 Bearer |

### `fileStorage`（接收落盘，可选）

| 字段 | 必填 | 默认 | 说明 |
|------|------|------|------|
| `tempDir` | 否 | `os.tmpdir()/a2a-files` | 本机保存 **收到的** inline 文件的目录；文件名 = 发送侧 basename（重名变为 `name (1).ext`） |

现网示例（HarmonyOS，以 shell 真实路径为准）：

| 设备 | `tempDir` |
|------|-----------|
| PC | `/storage/cloud/100/files/Docs/Download/OPENCLAW` |
| Phone | `/storage/media/100/local/files/Docs/OPENCLAW` |

> UI 显示的「下载路径」可能与 shell 路径不同（例如 PC 上并无 `/storage/Users/currentUser/...`）。配置前用 `hdc shell ls` / `touch` 验证。落盘与文件名规则见 [源码修改说明.md](./源码修改说明.md) §3。

### 会直接导致启动失败的配置

| 错误写法 | 结果 |
|----------|------|
| `enabled: true` 但没写 `relayUrl` 或 `deviceId` | 解析失败，插件起不来 |
| `relayUrl: "http://..."` | 解析失败（必须是 ws/wss） |
| peer 写了 `tunnelDeviceId` 但 `tunnel.enabled` 不是 true | 启动抛错 |
| `registry.enabled: true` 但没写 `baseUrl` | 解析失败 |
| `registry.enabled: true` 且没有 `serviceId` / `tunnel.deviceId` | 解析失败 |

### 混合模式（部分直连、部分隧道）

```json
{
  "tunnel": {
    "enabled": true,
    "relayUrl": "ws://中继:8080",
    "deviceId": "office-a"
  },
  "peers": [
    {
      "name": "局域网设备",
      "agentCardUrl": "http://192.168.1.50:18800/.well-known/agent-card.json"
    },
    {
      "name": "home-b",
      "tunnelDeviceId": "home-b",
      "agentCardUrl": "http://127.0.0.1:18800/.well-known/agent-card.json",
      "auth": { "type": "bearer", "token": "token-home-b" }
    }
  ]
}
```

- 没有 `tunnelDeviceId` → 直连（可用 gRPC）  
- 有 `tunnelDeviceId` → 走中继（仅 JSON-RPC / REST）

## 第 10 章：常见问题速查

| 现象 | 一步一步怎么查 |
|------|----------------|
| `plugins list` 没有 a2a-gateway | ① 是否 `install` 成功 ② `enabled` 是否 true ③ 是否重启 Gateway |
| curl 18800 连接拒绝 | ① `gateway status/restart` ② 日志有无 `HTTP listening` ③ 端口占用 |
| `test:tunnel` 找不到 ws | 重新 `npm install` |
| 启动报缺 relayUrl/deviceId | `enabled` 为 true 时必须填这两项，或改回 `false` |
| 日志 tunnel 连接超时 | ① 中继是否在听 8080 ② 安全组 ③ `relayUrl` 主机/端口/ws 前缀 |
| `/list` 没有本机 | 本机日志是否 connected；deviceId 是否被另一连接挤掉 |
| send 超时 | `/list` 两边都在吗；`tunnelDeviceId` 拼写；对端 18800 |
| 401 | 按第 5.3 对照表重对令牌 |
| 想经 NAT 用 gRPC | 本版不支持；tunnel peer 只用 JSON-RPC/REST |
| `must NOT have additional properties`（registry） | 设备上的 `openclaw.plugin.json` 仍是旧 schema，需同步新插件文件后重启 |
| 已 registered 但 discovered count=0 | 对端是否也注册成功；解析是否认中心返回的 `id`/`metadata`（见源码修改说明 §5） |
| 发现有人但 `Device xxx not found` | 通讯录有、隧道无：对端未连上 `:8001` |

日志关键字：`a2a-tunnel:`、`a2a-gateway: tunnel`、`a2a-gateway: HTTP listening`、`a2a-registry:`。
