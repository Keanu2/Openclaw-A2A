# OpenClaw A2A 大文件 / 本地路径发送 / 聊天配对问题 — 修改说明

- **日期**：2026-07-28
- **范围**：华为 HarmonyOS 双端（PC `HW-PC1` + 手机 `HW-Phone1`）+ 源码仓 `Openclaw-A2A`
- **目的**：支持最大约 50MB 的 A2A 内联文件传输；用「读本地路径」代替把 base64 塞进 CLI；消除聊天里「没配对 / 没权限」的误导

---

## 1. 背景与问题

| 问题 | 现象 | 根因 |
|------|------|------|
| CLI 传大文件失败 | `E2BIG` / `Argument list too long` | `openclaw gateway call a2a.send --params '{...巨大 base64...}'` 把整段参数放进 argv，OpenHarmony `ARG_MAX` ≈ 128KB |
| PC 内联上限偏小 | 大图被拒 | PC `maxInlineFileSizeBytes` 未提到 50MB（手机侧已是 50MB） |
| 聊天传图库失败 | Agent 说「没有配对设备」「没权限」 | 把 **SoftBus 设备配对** 和 **A2A peer** 混为一谈；`harmony-softbus` 插件本身损坏且无用 |
| 自定义插件改了不生效（手机） | `unknown method: a2a.send_local_file` | 手机 bundled 副本优先加载：`/data/local/npm/lib/node_modules/openclaw/extensions/a2a-gateway/`，自定义 extensions 被当作 duplicate 覆盖掉 |

成功验证：手机图库原图  
`/storage/media/100/local/files/Photo/16/IMG_1785225401_000.jpg`（1671574 bytes）  
经 `a2a.send_local_file` → PC `/data/local/tmp/a2a-files/`，MD5 均为  
`fbadf987df862ec15d9913d9b4c2b1ff`。

## 5. 为什么要这么改

### 5.1 50MB 配置

- 内联 FilePart（base64）受 `maxInlineFileSizeBytes` 限制；URI 文件受 `maxFileSizeBytes` 限制。
- 手机已是 50MB，PC 不一致会导致「一端能发、一端拒收」或行为难预期。
- 50MB 仍低于多数业务需要无限大文件的场景，但覆盖常见照片/文档；更大应走 URI/分块（当前未做）。

### 5.2 `a2a.send_local_file` / `a2a_send_local_file`

- **根因**：shell/`gateway call --params` 无法承载 MB 级 base64。
- **做法**：params 只传短字符串路径；在 **gateway 进程内**读盘编码，再走现有 A2A 发送逻辑。
- **对比** `node a2a-send.mjs --file-path`：也能避 ARG_MAX，但默认硬编码 10MB，且直连 peer URL，不经过本机 peer 名 + tunnel 配置；双端 NAT 场景更适合 gateway 方法。

### 5.3 SoftBus 关闭 + TOOLS.md

- SoftBus 插件缺依赖（如 `plugin-sdk/root-alias` 一类），无法正常「配对」。
- A2A 传文件只依赖：本机 gateway + a2a-gateway 插件 + relay 上两端 online + 正确 peer 名。
- Agent 读 TOOLS.md 后应调用 `a2a_send_local_file`，而不是 SoftBus 或 `a2a_send_file`（后者要公网 URI）。

### 5.4 必须改手机 bundled 副本

- OpenClaw 会加载包内 `extensions/a2a-gateway`；与自定义同 id 时 **先加载的生效，后加载的被 override**。
- 只改 `/data/local/.openclaw/extensions/...` 在手机上不够。

---

## 6. 这么改带来的好处

1. **大文件可传**：典型 1～数 MB 照片不再因 E2BIG 失败；上限与配置对齐到 50MB。
2. **聊天可操作**：Agent 有明确工具 `a2a_send_local_file`，参数小、语义清晰。
3. **路径安全边界**：限制在媒体/数据目录前缀，降低误读系统敏感路径风险。
4. **概念澄清**：不再依赖已损坏的 SoftBus「配对」叙事，减少假错误信息。
5. **运维可重启**：start 脚本能杀掉真正的 `openclaw-gateway` 进程，避免 TIME_WAIT / 旧进程假活。
6. **可验证**：同文件 MD5 端到端一致，便于回归。

## 7. 用法速查

### Gateway CLI（推荐测大文件）

```bash
export HOME=/data/local
export OPENCLAW_STATE_DIR=/data/local/.openclaw
export OPENCLAW_CONFIG_PATH=/data/local/.openclaw/openclaw.json

# 手机 → 电脑
openclaw gateway call a2a.send_local_file --timeout 300000 \
  --params '{"peer":"HW-PC1","path":"/storage/media/100/local/files/Photo/16/IMG_1785225401_000.jpg"}'

# 电脑 → 手机
openclaw gateway call a2a.send_local_file --timeout 300000 \
  --params '{"peer":"HW-Phone1","path":"/storage/media/100/local/files/Docs/Desktop/Sunflower.jpeg"}'
```

### 聊天窗口

让 Agent 调用工具 **`a2a_send_local_file`**（不要用 SoftBus，不要用仅支持 URI 的 `a2a_send_file`）。

### 不要再这样做

```bash
# 会 E2BIG（大文件）
openclaw gateway call a2a.send --params '{"message":{"parts":[{"kind":"file","file":{"bytes":"<MB级base64>"}}]}}'
```

## 8. 集成版 OpenClaw 要不要重新更新 / 打包？

**要——如果希望别人开箱即用同样能力。**

| 变更类型 | 是否必须进集成包 | 说明 |
|----------|------------------|------|
| `a2a-gateway` 插件 `index.ts`（`send_local_file`） | **是** | 这是代码能力；他人机器不会自动有 |
| 集成包内 bundled `openclaw/extensions/a2a-gateway/` | **是（强烈建议）** | 手机类布局会优先用 bundled；只改外部 extensions 可能被盖住 |
| 设备 `openclaw.json` 里 50MB | **建议作为默认配置模板** | 否则别人仍是插件 schema 默认 10MB inline |
| SoftBus `enabled: false` | 按产品决定 | 若集成里 SoftBus 仍不可用，建议默认关或修好再开 |
| 各设备 `TOOLS.md` / launcher / hdc PATH | **否（环境文档）** | 不进核心包也可；可作为样机预设或文档附带 |
| 本 CHANGELOG | 文档 | 建议放进仓库 `docs/` |

**推荐发布流程：**

1. 把 `Openclaw-A2A`（或你们合并进 monorepo 的同一插件）合入集成版源码。
2. 同步覆盖集成包内 `extensions/a2a-gateway`（避免双份漂移）。
3. 更新默认配置示例：`maxInlineFileSizeBytes` / `maxFileSizeBytes` = 52428800（若产品接受 50MB）。
4. 重新构建 / 打包 OpenClaw（含 OH 目标产物）。
5. 发版说明写上：新方法 `a2a.send_local_file`、工具 `a2a_send_local_file`、与 SoftBus 无关。

**若暂时不重新打包：**  
可在每台已部署设备上手动推送 `index.ts`（含 bundled 路径）并改配置——仅适用于你们自己的样机，**不能**让外部用户自动获得该能力。
