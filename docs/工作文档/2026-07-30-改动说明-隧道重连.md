## 1. 背景：为什么要改

2026-07-30 用 hdc 排查 PC（`HW-PC1` / MateBook Pro）与手机（`HW-Phone1` / Mate 60 Pro）连中继 `ws://121.37.53.35:8001` 频繁断开问题，结论如下。

### 1.1 现象

- 两端都能连上中继；短时跨端 `a2a.send` 可成功。
- 约数分钟后，**手机侧**持续收到：`Device HW-PC1 disconnected` / `Device HW-PC1 not found`。
- **PC 侧**长时间不出现 `websocket closed`，TCP 仍显示 `ESTABLISHED`，但 **Send-Q 持续上涨**（半死连接 / 假在线）。
- 旧逻辑默认 **`maxReconnectAttempts=10`**：重连失败约 10 次后打印 `max reconnect attempts reached`，**之后永久不再连**，直到人工重启 gateway。
- 历史日志中还出现过约 **每 5 分钟** 一次 `websocket closed`（两端都有），更像中继/中间网络对长连接不友好。

### 1.2 根因分层

| 层级 | 结论 |
|------|------|
| 网络路径 | PC 走 `10.23.182.91`（`wlan0` → `10.23.182.1`），手机走 `100.125.153.249`（另一 Wi‑Fi 网段）。**不是同一条路上网**，PC 路径更易假死。 |
| 中继/链路 | 连接会被掐或变哑；客户端只靠 `close` 事件，**发现不了半死连接**。 |
| 旧客户端 | 心跳只发应用层 JSON `PING`，**不检测是否收到回包**；重连有硬上限 10 次。 |

本次源码改造针对 **客户端重连与假死检测**，不替代中继侧超时排查。

## 3. 行为对比（旧 → 新）

| 能力 | 旧（≤1.4.2） | 新（1.4.3） |
|------|--------------|-------------|
| 重连次数上限 | 默认 **10**，用尽后永久放弃 | 默认 **0 = 无限** |
| 假死检测 | 无；只等 `websocket closed` | **`heartbeatTimeoutMs`（默认 45s）内无任何入站流量 → `terminate` 并重连** |
| 心跳 | 仅 JSON `PING` | JSON `PING` + WebSocket 协议层 `ping()`；任意入站消息 / `pong` 刷新 `lastRecvAt` |
| 重连间隔 | 固定 `reconnectIntervalMs`（默认 5s） | **指数退避**：5s → 10s → … 封顶 `maxReconnectIntervalMs`（默认 60s） |
| 重连并发 | 可能重复调度 | `reconnectScheduled` 防重入 |
| 注册失败 | 可能留下半开 socket | `forceCloseSocket()` 强制拆除后再排重连 |
| 重连成功日志 | 静默（仅首次 `connected as`） | 额外：`a2a-tunnel: reconnected as …` |

## 4. 新增 / 调整配置项

路径：`plugins.entries.a2a-gateway.config.tunnel`

| 字段 | 默认 | 含义 |
|------|------|------|
| `heartbeatIntervalMs` | `15000` | 多久发一次心跳 |
| `heartbeatTimeoutMs` | **`45000`（新）** | 多久没收包就强制重连 |
| `reconnectIntervalMs` | `5000` | 退避基数 |
| `maxReconnectIntervalMs` | **`60000`（新）** | 退避上限 |
| `maxReconnectAttempts` | **`0`（改默认）** | `0`=无限；`>0` 为硬上限 |

示例（可选，不写则用默认）：

## 5. 关键实现要点（`session.ts`）

1. **`lastRecvAt`**：`message` / 协议 `pong` / `open` 时更新。  
2. **心跳定时器**：若 `now - lastRecvAt >= heartbeatTimeoutMs` → 打 warn：`heartbeat timeout … forcing reconnect` → `ws.terminate()`。  
3. **`scheduleReconnect`**：`maxReconnectAttempts===0` 时日志显示 `∞`；延迟 `min(base * 2^(n-1), maxInterval)`。  
4. **`forceCloseSocket`**：半死连接优先 `terminate()`，依赖 `close` 回调再入队重连；无 socket 时直接 `scheduleReconnect`。  
5. **重连成功**：`startHeartbeat()` + `reconnected as` 日志；`reconnectAttempts` 在 register 成功后清零。

## 6. 预期日志关键字

| 场景 | 日志 |
|------|------|
| 首次连上 | `a2a-tunnel: connected as HW-…` |
| 假死检出 | `a2a-tunnel: heartbeat timeout (…ms without recv), forcing reconnect` |
| 普通断开 | `a2a-tunnel: websocket closed` |
| 排队重连 | `a2a-tunnel: reconnecting (N/∞) in Xms` |
| 重连成功 | `a2a-tunnel: reconnected as HW-…` |
| 仍失败 | `a2a-tunnel: reconnect failed: …`（会继续排下次，默认不会再出现 max reached） |

若仍看到 `max reconnect attempts reached`，说明设备上跑的还是旧副本，或配置里显式写了 `maxReconnectAttempts>0`。

## 7. 验证建议

1. 看 stdout / `openclaw.log` 是否两边都有 `connected as`。  
2. 跨端：`openclaw gateway call a2a.send --timeout 60000 --params '{"peer":"HW-Phone1","message":{"text":"…"}}'`。  
3. 空闲观察 **≥10 分钟**：PC 若假死，应在约 45s 无收包后出现 `heartbeat timeout` 并自动 `reconnected`，而不是一直 `Device HW-PC1 not found` 且永不回来。  
4. 长期仍频繁假死：继续查 **PC 所在 `10.23.x` Wi‑Fi / 中继空闲超时**（客户端只能自愈，不能消灭根因）。
