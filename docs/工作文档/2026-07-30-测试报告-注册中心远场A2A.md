# 测试报告：注册中心远场 A2A

日期：2026-07-30  
版本：`1.4.3-tunnel.2`  
验收目标：两端向注册中心注册/发现，**不依赖手写对端 peers**，跨网经 `ws://121.37.53.35:8001` 完成至少一次文本 `a2a.send`。

## 环境

| 项 | 值 |
|----|-----|
| 注册中心 | `http://121.37.53.35:8000` |
| 隧道中继 | `ws://121.37.53.35:8001` |
| Dataset | `openclaw_devices` |
| PC | `HW-PC1`（hdc `3QC0225430004479`） |
| Phone | `HW-Phone1`（hdc `FMR0223926019410`） |
| 配置模式 | `peers: []` + `registry.enabled` + `defaultPeerAuth`（发现-only） |

## 步骤与结果

| # | 步骤 | 结果 |
|---|------|------|
| 1 | `GET /api/warmup-status`（设备侧） | **通过** `ready=true`（Windows 直连曾 502，以设备可达为准） |
| 2 | 两端开 `registry` 并重启 gateway | **通过** 日志：`a2a-registry: registered` + `tunnel connected` |
| 3 | `GET .../datasets/openclaw_devices/services` | **通过** 同时可见 `HW-PC1`、`HW-Phone1`；Card 在 `metadata`，id 字段为 `id` |
| 4 | PC 发现动态 peer | **通过** `discovered peers: {"count":1,"names":["HW-Phone1"]}`（静态 peers 为空） |
| 5 | PC → Phone `a2a.send` 文本 | **通过**（见下） |

### a2a.send 成功摘录

```text
Gateway call: a2a.send
statusCode: 200
peer: HW-Phone1（来自注册中心发现，非静态配置）
user message: "ping registry farfield reply ok"
response artifact: "HEARTBEAT_OK"
task state: completed
```

通信路径：PC 插件经隧道 `forward_request` → 中继 → Phone 本机 `127.0.0.1:18800` → 响应回程。

## 实现要点

- `src/registry-client.ts`：ensureDataset / registerA2a / listServices / 周期 discover
- Card `metadata.tunnelDeviceId` 写入（HTTP 注册 + 旧中继 auto-bind 路径）
- Tunnel REGISTER：启用 registry 时发送增强字段（`dataset`/`service_id`/`agent_card`），中继拒识则回退仅 `device_id`；HTTP 注册 + Card `metadata.tunnelDeviceId` 做绑定
- 发现解析兼容中心实际返回：`id` + `metadata`（非 `service_id`/`agent_card`）

## 失败与规避

| 现象 | 处理 |
|------|------|
| Windows 探活 502 | 改从 Phone/PC 探活 |
| Phone `must NOT have additional properties` | 同步 schema 到 `/data/local/npm/.../extensions/a2a-gateway/` |
| 发现 count=0 但中心已有两台 | 修正 list 解析（`id`/`metadata`） |
| 首次 send 超时 / `Device HW-Phone1 not found` | 对端隧道短暂掉线；重启后短文本 ping 成功 |

## 结论

**远场注册中心流程已跑通**：注册 → 发现 → 隧道 A2A 文本往返成功，且发送侧未手写对端 Card/peer。
