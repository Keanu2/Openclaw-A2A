# 规范说明：扩展文件类型与路径

> **文档位置**：`docs/工作文档/2026-07-31-规范说明-扩展文件类型与路径.md`  
> **相关能力**：`a2a_send_local_file` / `a2a.send_local_file`（发）+ 对端 `executor` 落盘（收）  
> **整理日期**：2026-07-31  
> **目的**：以后要放行更多 MIME、更多本机目录、改接收落盘位置时，知道改哪个文件、怎么改、改完有什么效果。

---

## 0. 先分清三件事

发文件时插件会做三类校验；扩展时对症下药：

| 你想改什么 | 卡在哪 | 优先怎么改 |
|------------|--------|------------|
| **允许的类型**（pdf/zip/office…） | MIME 白名单 | 配 `security.allowedMimeTypes`（配置） |
| **扩展名自动识别不准** | `MIME_MAP` | 改源码 `src/file-security.ts`，或调用时传 `mimeType` |
| **本机能从哪个目录发** | 路径前缀白名单 | 改源码 `index.ts` 的 `isAllowedLocalPath` |
| **对端收到后存哪** | 接收落盘目录 | 配 `fileStorage.tempDir`（已接通，见 §4） |
| **接收文件名** | 原名 / UUID | 现已保留原名；重名加 ` (n)`（见 §4.5） |
| **最大多大** | 大小上限 | 配 `security.maxInlineFileSizeBytes`（两端都要够） |

```text
发送侧：path 白名单 → 读文件 → 猜/指定 MIME → MIME 白名单 → 大小检查 → base64 → A2A
接收侧：解 base64 → 按原文件名落盘到 fileStorage.tempDir（冲突加序号）
```

> **2026-07-31 设备现状与改动细节**见：  
> [`2026-07-31-改动说明-接收落盘与原文件名.md`](./2026-07-31-改动说明-接收落盘与原文件名.md)

下文「设备配置」指两端 `openclaw.json` 里：

```text
plugins.entries.a2a-gateway.config
```

HarmonyOS 常见路径：`/data/local/.openclaw/openclaw.json`。改完需**重启 gateway**。

## 1. 扩展允许的文件类型（MIME 白名单）

### 1.1 改哪里

| 位置 | 路径 | 是否必须改源码 |
|------|------|----------------|
| **设备配置（推荐）** | `openclaw.json` → `...config.security.allowedMimeTypes` | 否 |
| Schema 说明（可选） | 仓库 `openclaw.plugin.json` → `security.allowedMimeTypes` | 否（只影响文档/校验提示） |
| 代码默认值（未配数组时） | 仓库 `index.ts` → `parseConfig` 里的 `defaultMimeTypes` | 仅当想改「全局默认」 |

### 1.2 当前默认（配置里没写 `allowedMimeTypes` 时）

源码 `index.ts` 的 `defaultMimeTypes` 大致包括：

- `image/*`、`audio/*`、`video/*`
- `application/pdf`、`text/plain`、`text/markdown`、`text/csv`、`application/json`
- Office：`docx` / `xlsx` / `pptx` 及旧版 `doc` / `xls` / `ppt` 对应 MIME

**注意：** 一旦在配置里写了 `allowedMimeTypes`（非空数组），**完全以你写的为准**，默认列表不再合并。

### 1.3 怎么改（配置示例）

在发送端（以及若要对「入站 URI 文件」一致，两端都建议对齐）增加：

```json
{
  "plugins": {
    "entries": {
      "a2a-gateway": {
        "config": {
          "security": {
            "allowedMimeTypes": [
              "image/*",
              "video/*",
              "audio/*",
              "application/pdf",
              "text/plain",
              "text/markdown",
              "application/json",
              "application/zip",
              "application/gzip",
              "application/octet-stream",
              "application/vnd.openxmlformats-officedocument.wordprocessingml.document",
              "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet",
              "application/vnd.openxmlformats-officedocument.presentationml.presentation"
            ],
            "maxInlineFileSizeBytes": 52428800,
            "maxFileSizeBytes": 52428800
          }
        }
      }
    }
  }
}
```

匹配规则（`src/file-security.ts` → `validateMimeType`）：

- 精确：`application/pdf` 只匹配 PDF  
- 通配：`image/*` 匹配 `image/png`、`image/heic` 等  
- 参数会剥掉：`text/plain; charset=utf-8` 按 `text/plain` 比  

### 1.4 修改后的效果

| 改前 | 改后 |
|------|------|
| 不在默认列表的 MIME → `MIME type rejected: "..."` | 在你列表里的类型可通过校验并发送 |
| 未配置时用代码默认 | 配置后只用你的列表 |

调用示例（CLI）：

```bash
openclaw gateway call a2a.send_local_file --timeout 300000 --params '{
  "peer":"HW-Phone1",
  "path":"/data/local/tmp/demo.zip",
  "mimeType":"application/zip"
}'
```

Agent 工具同理：`a2a_send_local_file`，参数 `peer` + `path`，可选 `mimeType`。

### 1.5 只改默认列表（所有未自定义配置的部署）

文件：`index.ts`（`parseConfig` 内）

```ts
const defaultMimeTypes = [
  "image/*", "application/pdf", /* ... */,
  "application/zip",           // 新增示例
];
```

效果：凡配置里**没写** `allowedMimeTypes` 的环境，自动允许这些类型。已手写数组的环境不受影响。

## 2. 扩展「扩展名 → MIME」自动识别

发送时若**不传** `mimeType`，会走：

`detectMimeType(path)` → 查 `MIME_MAP` → 没有则 `application/octet-stream`。

即使白名单开了 `application/zip`，若扩展名未映射且你又没传 `mimeType`，仍可能被当成 `octet-stream`；若白名单没有 `octet-stream`，就会被拒。

### 2.1 改哪里

| 文件 | 仓库路径 | 改什么 |
|------|----------|--------|
| **`src/file-security.ts`** | 发送侧扩展名映射 `MIME_MAP` | 增加 `".xxx": "mime/type"` |
| （可选）调用参数 | CLI / Tool 的 `mimeType` | 不改源码，单次覆盖 |

### 2.2 怎么改

在 `src/file-security.ts` 的 `MIME_MAP` 中增加，例如：

```ts
const MIME_MAP: Record<string, string> = {
  // ...原有...
  ".zip": "application/zip",
  ".7z": "application/x-7z-compressed",
  ".apk": "application/vnd.android.package-archive",
};
```

同时务必保证发送端 `allowedMimeTypes` 包含对应 MIME（或通配）。

### 2.3 修改后的效果

| 场景 | 效果 |
|------|------|
| `path` 以 `.7z` 结尾且未传 `mimeType` | 自动带上你映射的 MIME，再走白名单 |
| 仍被拒 | 检查白名单是否包含该 MIME |
| 不想改源码 | 调用时显式 `"mimeType":"application/x-7z-compressed"` |

### 2.4 部署

改完源码后，用 hdc 覆盖设备上实际加载的插件副本（与以往相同），例如：

- `/data/local/.openclaw/workspace/plugins/a2a-gateway/`
- `/data/local/.openclaw/extensions/a2a-gateway/`
- Phone 常还有：`/data/local/npm/lib/node_modules/openclaw/extensions/a2a-gateway/`

至少同步 `src/file-security.ts`（及若改了 `index.ts` 则一并同步），然后重启 gateway。

## 3. 扩展本机「允许发送的路径」

本地发文件入口都会先过路径白名单（`sendLocalFileCore` → `isAllowedLocalPath`）。

### 3.1 改哪里

| 文件 | 仓库路径 | 说明 |
|------|----------|------|
| **`index.ts`** | 函数 `isAllowedLocalPath` 内数组 `allowedPrefixes` | **当前写死在源码，无配置项** |

现有前缀（`1.4.3-tunnel.3`）：

```ts
const allowedPrefixes = [
  "/data/local/",
  "/storage/media/",
  "/storage/cloud/",   // PC 下载区真实路径前缀
  "/storage/Users/",   // 预留 UI 风格路径
  "/mnt/user/",
  "/mnt/hmdfs/",
  "/home/",
];
```

其它硬性规则（一般不要放宽）：

- 必须是**绝对路径**
- 禁止路径含 `\0`
- 必须是普通文件（不能是目录）

### 3.2 怎么改（示例：允许 `/sdcard/`）

```ts
const allowedPrefixes = [
  "/data/local/",
  "/storage/media/",
  "/storage/cloud/",
  "/storage/Users/",
  "/mnt/user/",
  "/mnt/hmdfs/",
  "/home/",
  "/sdcard/",           // 新增
  "/storage/emulated/", // 按需
];
```

前缀请带尾部 `/`，与现有写法一致。匹配时会对 Windows 盘符、反斜杠做规范化，HarmonyOS 上主要看 POSIX 路径。

### 3.3 修改后的效果

| 改前 | 改后 |
|------|------|
| `Path rejected: path not in allowed roots (...)` | 该前缀下的绝对路径可通过校验并读取发送 |
| 相对路径如 `./a.png` | 仍拒绝（必须绝对路径） |

验证：

```bash
# 应成功（前缀已放行且文件存在）
openclaw gateway call a2a.send_local_file --params '{
  "peer":"HW-Phone1",
  "path":"/sdcard/Download/demo.png"
}'
```

### 3.4 安全提示

路径白名单是防 Agent/工具乱读系统敏感目录的。只加**业务确实需要**的根目录，不要改成「任意路径都可」。

## 4. 扩展 / 修改「接收落盘」目录与文件名

对端收到 inline 文件后，在 `src/executor.ts` 里 `saveBase64File` 写盘。

### 4.1 现状（`1.4.3-tunnel.3`，已接通）

| 组件 | 状态 |
|------|------|
| `src/types.ts` | `fileStorage?: { tempDir: string }` |
| `src/executor.ts` | 读 `config.fileStorage?.tempDir`；**按原文件名落盘**；冲突加 ` (n)` |
| `index.ts` → `parseConfig` | **已解析** `fileStorage.tempDir` |
| `openclaw.plugin.json` | **已有** `fileStorage` schema |

未配置 `fileStorage.tempDir` 时，回退：`os.tmpdir() + "/a2a-files"`。

### 4.2 改落盘目录（推荐：只改设备配置）

在该设备 `/data/local/.openclaw/openclaw.json`：

```json
"plugins": {
  "entries": {
    "a2a-gateway": {
      "config": {
        "fileStorage": {
          "tempDir": "/storage/media/100/local/files/Docs/OPENCLAW"
        }
      }
    }
  }
}
```

然后重启 gateway。

**效果：** 新收到的 inline 文件进入该目录；历史文件不自动搬迁。

### 4.3 现网已配置值（2026-07-31）

| 设备 | `fileStorage.tempDir`（写入配置的真实路径） | 备注 |
|------|---------------------------------------------|------|
| PC HW-PC1 | `/storage/cloud/100/files/Docs/Download/OPENCLAW` | UI 上可能显示成 `/storage/Users/currentUser/Download/OPENCLAW`，**shell 下后者不存在**，必须以 cloud 路径配置 |
| Phone HW-Phone1 | `/storage/media/100/local/files/Docs/OPENCLAW` | 与用户描述一致 |

改路径前请在设备上验证：

```sh
hdc shell "ls -la <目标目录>; touch <目标目录>/.write_test && rm <目标目录>/.write_test"
```

### 4.4 若必须改源码默认（无配置时的回退）

**文件：** `src/executor.ts` 构造函数附近：

```ts
fileTempDir = config.fileStorage?.tempDir || path.join(os.tmpdir(), "a2a-files");
```

把右侧 fallback 换成你的默认绝对路径即可。有配置时仍以配置为准。

### 4.5 文件名规则（已实现，一般不用再改）

| 规则 | 行为 |
|------|------|
| 原名 | 使用 FilePart 的 `name`（**本地路径发送时强制为** `basename(path)`，忽略调用方 `name`） |
| 净化 | 去掉路径分量、控制字符、`<>:"|?*`；最长 180 |
| 无扩展名 | 用接收侧 `MIME_TO_EXT` / 内容嗅探补后缀 |
| 重名 | `a.jpg` → `a (1).jpg` → `a (2).jpg` |
| 权限 | 写盘 `0o664`，并尽量 `chown` 为目录属主（便于文件管理器打开） |

相关函数：`sanitizeFileName`、`uniquePathForName`、`saveBase64File`（均在 `src/executor.ts`）。

### 4.6 接收侧扩展名映射（落盘后缀）

当**原名没有扩展名**时，扩展名来自 `src/executor.ts` 的 `MIME_TO_EXT`（不是发送侧的 `MIME_MAP`）。

若新类型变成 `.bin`，在 **接收端** 同步改：

```ts
const MIME_TO_EXT: Record<string, string> = {
  // ...原有...
  "application/x-7z-compressed": ".7z",
};
```

原名已带正确扩展名时，一般无需改此表。

## 5. 放大可传文件体积

### 5.1 改哪里

| 配置项 | 作用 |
|--------|------|
| `security.maxInlineFileSizeBytes` | **本地路径发文件**（inline base64）上限，默认 50MB |
| `security.maxFileSizeBytes` | **URI 方式**拉文件的上限 |
| `tunnel.requestTimeoutMs` | 大文件经隧道时的转发超时 |
| `timeouts.agentResponseTimeoutMs` | 对端 Agent 处理超时（聊天路径） |

两端 `openclaw.json` 建议一致，例如 100MB：

```json
"security": {
  "maxInlineFileSizeBytes": 104857600,
  "maxFileSizeBytes": 104857600
},
"tunnel": {
  "requestTimeoutMs": 1200000
}
```

### 5.2 效果

- 超过上限：`File size xMB exceeds limit yMB`  
- 调大后：在新上限内可通过；内存与隧道耗时会上升，需实测  

仓库默认值也在 `index.ts` 的 `parseConfig` 与 `openclaw.plugin.json` 的 `default` 字段；只改设备配置即可覆盖运行时行为。

## 6. 公网 URI 发文件的路径/域名（补充）

若用的是 **`a2a_send_file`（URI）** 而不是本地路径：

| 配置 | 文件位置 | 效果 |
|------|----------|------|
| `security.fileUriAllowlist` | `openclaw.json` | 限制可拉的主机名，如 `"*.example.com"`；空 = 不限制公网 host（仍拦私网 IP） |

本地路径白名单**不作用于** URI 模式。

## 7. 场景清单（照着做）

### 场景 A：允许发 `.zip`，目录已在白名单内

1. 配置增加 `allowedMimeTypes`（含 `application/zip`）——见 §1  
2. 确认 `MIME_MAP` 已有 `.zip`（当前源码已有）  
3. 重启发送端 gateway  
4. `a2a.send_local_file` 指向 `/data/local/.../x.zip`  

**效果：** zip 可发；对端落盘扩展名依赖接收端 `MIME_TO_EXT`（已有 `application/zip` → `.zip`）。

### 场景 B：允许从 `/sdcard/Download/` 发照片

1. 改 `index.ts` → `allowedPrefixes` 加 `"/sdcard/"` 或更精确前缀——见 §3  
2. 同步 `index.ts` 到设备插件目录  
3. 重启；确认 `image/*` 仍在白名单（默认已有）  

**效果：** 该目录下绝对路径不再 `Path rejected`。

### 场景 C：新类型 `.apk`

1. `file-security.ts` 的 `MIME_MAP` 加 `".apk": "application/vnd.android.package-archive"`  
2. 配置 `allowedMimeTypes` 加入该 MIME（或临时用 `application/octet-stream` + 显式 `mimeType`）  
3. 接收端 `executor.ts` 的 `MIME_TO_EXT` 加对应项（否则可能存成 `.bin`）  
4. 同步源码、重启两端  

**效果：** 发送识别正确、白名单通过、对端落盘扩展名正确。

### 场景 D：接收统一存到固定目录

改设备 `fileStorage.tempDir`（§4.2），重启 gateway。  

**效果：** Agent 回报的「保存路径」前缀变为新目录；文件名仍为原名。

### 场景 E：确认「原文件名」落盘（现网已开）

用 `a2a_send_local_file` 发本地文件时**不要传 `name`**（传了也会被忽略）；传输名 = `basename(path)`。在接收目录 `ls` 应看到与源文件同名的文件，而不是 UUID / `file.jpg`。  
聊天回报路径必须是 `fileStorage.tempDir` 下的绝对路径，禁止改写成 `/data/local/tmp/a2a-files/`。详见 [`2026-08-03-改动说明-传输文件名与路径回报.md`](./2026-08-03-改动说明-传输文件名与路径回报.md)。

## 9. 常见报错对照

| 报错 / 现象 | 原因 | 处理 |
|-------------|------|------|
| `Path rejected: path not in allowed roots` | 发送路径不在前缀白名单 | §3 加前缀 |
| `path must be absolute` | 传了相对路径 | 改用绝对路径 |
| `MIME type rejected: "..."` | 不在 `allowedMimeTypes` | §1 加 MIME，或传对的 `mimeType` |
| 未传 mime 却变成 `application/octet-stream` 被拒 | 扩展名不在 `MIME_MAP` | §2 加映射，或显式 `mimeType` |
| `File size ... exceeds limit` | 超过 inline/URI 上限 | §5 调大两端配置 |
| 对端保存成 `.bin` | 原名无扩展且 `MIME_TO_EXT` 无映射 | §4.6 |
| 配了 `fileStorage` 仍进临时目录 | schema 旧 / 未同步插件 / 未重启 | 同步 `openclaw.plugin.json` + 重启；见改动说明 §6 |
| UI 路径配置后目录不存在 | UI 路径 ≠ shell 真实路径 | 用 `hdc shell ls` 找真实路径再写入（PC 见 cloud Download） |
| 文件名仍是 UUID | 设备上仍是旧 `executor.ts` | 同步 `src/executor.ts` 并重启 |
| 文件名变成 `file.jpg` 等编造名 | 发送侧仍尊重 `params.name`（旧 `index.ts`） | 同步含强制 basename 的 `index.ts`；见 08-03 改动说明 |
| 聊天路径仍是 `/data/local/tmp/a2a-files/` | TOOLS/MEMORY 未更新，或模型改写 | 推送现行 TOOLS/MEMORY；核对入站文案含「禁止改写」 |

## 11. 一句话建议

- **只加类型**：优先改设备 `security.allowedMimeTypes`；扩展名不对再改 `MIME_MAP` 或传 `mimeType`。
