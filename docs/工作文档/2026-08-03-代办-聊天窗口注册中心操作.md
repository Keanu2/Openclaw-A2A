# 代办：聊天窗口操作注册中心（注册 / 列举 / 发现）

---

## 1. 背景

当前注册中心能力在 gateway **启动时自动**完成：

- `registerOnStart` → 向中心注册本机 Agent Card  
- 周期 `discover` → 拉 list，合并进本机 peers  

聊天窗口**没有**对应 Agent Tool / gateway method。用户无法用自然语言让当前 Agent：

- 「在注册中心注册一下」  
- 「注册中心现在有哪些设备」  
- （可选）「重新发现一下 peer」  

通信本身仍走隧道，与本代办无关；本代办只补**可观测 / 手动触发**的通讯录操作。

---

## 2. 目标（实现时）

在 OpenClaw 聊天中，通过工具调用完成：

| 用户说法（示例） | 期望行为 |
|------------------|----------|
| 在注册中心注册一下 | 立刻对本机执行一次 registry register |
| 注册中心现在在线的设备有哪些 | 拉中心 list，列举服务 id/名称（见下方「在线」说明） |
| （可选）重新发现一下 | 强制 refresh，更新本机 discovered peers |

**不替代**启动时自动注册 / 定时发现；聊天工具为补充入口。

---

## 3. 建议实现（最小集）

### 3.1 工具 / 方法（名称可调整）

| 名称 | 类型 | 行为 |
|------|------|------|
| `a2a_registry_register` | Tool + 可选 gateway method | 调用现有 `RegistryClient.registerA2a`（需已配置 registry） |
| `a2a_registry_list` | Tool + 可选 gateway method | 调用 `listServices`，格式化返回 id / name 等 |
| `a2a_registry_refresh`（可选） | Tool | 调用 `refresh()`，回报 discovered 列表 |

### 3.2 前置条件

- `openclaw.json` 已配 `registry.baseUrl` / `dataset` / `serviceId`（或 `tunnel.deviceId`）  
- 未配置时工具应明确报错，不要静默失败  

### 3.3 设备提示词

实现时同步改两端 `TOOLS.md`（及必要时 `MEMORY.md`）短规则，否则 Agent 不一定会选用这些工具。

### 3.4 话术注意：「在线」≠「在通讯录」

中心 list 通常表示**已注册服务**，不等于隧道此刻已连接。  
对用户应优先说「已注册设备」；若以后要真·在线，需另查中继/隧道状态（超出本最小集）。

---

## 4. 明确不做（本代办范围外）

- 拆分 `registry.enabled` 为「只注册 / 只发现」两个开关（另议，当前无必要）  
- 用注册中心 HTTP 做远场消息通道（通信仍走隧道）  
- 注册中心服务端改动  

---

## 5. 验收草案（实现后）

1. 聊天：「在注册中心注册一下」→ 工具成功，中心 list 可见本机 `serviceId`  
2. 聊天：「注册中心有哪些设备」→ 列出至少本机 + 对端（若对端已注册）  
3. （若做 refresh）聊天触发后，本机 `a2a.send` 可用发现到的 peer 名  
4. `registry` 未配置时，工具返回清晰错误文案
