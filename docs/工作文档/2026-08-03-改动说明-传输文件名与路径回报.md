## 1. 背景与目标

### 1.1 问题现象（用户反馈）

在已接通 `fileStorage.tempDir`、接收侧已按 FilePart `name` 落盘之后，仍出现：

1. **文件名不对**  
   本地明明是 `IMG_xxx.jpg` / `hello-filename-test.txt`，对端却常落成 `file.jpg` 或其它模型编造名。  
2. **聊天路径不对**  
   磁盘上已在 `.../OPENCLAW/...`，聊天却仍回报 `/data/local/tmp/a2a-files/<uuid>.jpg`（旧习惯路径）。

### 1.2 根因

| # | 层 | 根因 |
|---|-----|------|
| 1 | **发送源码** | `sendLocalFileCore` 曾允许 `params.name` 覆盖 basename；聊天 Agent 经常自创 `file.jpg` |
| 2 | **接收侧实际落盘** | 其实已按 FilePart.name 写到 OPENCLAW（日志/ls 正确） |
| 3 | **Agent 话术** | 设备 `TOOLS.md` / `MEMORY.md` 收件栏仍写 `/data/local/tmp/a2a-files/`，模型把真实路径改写成记忆中的旧目录 |

### 1.3 验收目标

1. 故意传 `name: "file.jpg"`，源路径 basename 为 `IMG_realname_1724.txt` → 对端磁盘文件名必须是 **`IMG_realname_1724.txt`**。  
2. 对端 Agent 聊天回报的「保存路径」必须是 **`fileStorage.tempDir` 下的绝对路径**，不得出现 `/data/local/tmp/a2a-files/`。

## 3. 每个文件具体怎么改、为什么

### 3.1 `index.ts` — `sendLocalFileCore` 强制 basename

#### 旧逻辑（问题）

```ts
const name =
  (params.name && String(params.name).trim()) ||
  path.basename(filePath);
```

Agent 工具调用常见：

```json
{ "peer": "HW-Phone1", "path": "/.../IMG_1785225401_000.jpg", "name": "file.jpg" }
```

结果：FilePart.name = `file.jpg` → 对端保存为 `file.jpg`，与源文件不一致。

#### 新逻辑

```ts
// Wire name MUST follow the real local basename so the peer saves the same name.
// Do not trust params.name (agents often invent "file.jpg").
const name = path.basename(filePath);
```

Gateway 方法仍可把 `params.name` 传入 core 的参数对象，但 **core 内不再使用该字段**。

#### Tool schema

```ts
path: {
  description: "Absolute local file path ... Wire filename = basename(path)."
},
name: {
  description: "Ignored: transmission filename is always basename(path) so peer saves the same name."
},
```

**效果：** 无论聊天是否传 `name`，线上 FilePart.name = 本地 basename；对端按同名落盘。

### 3.2 `src/executor.ts` — 入站话术

成功落盘后生成（节选）：

```text
【A2A 文件接收成功】
传输文件名: <FilePart.name>
落盘文件名: <path.basename(savedPath)>
...
保存路径: <绝对路径>

请在聊天窗口用中文明确告知用户：接收成功。
必须原样完整报出上一行「保存路径」的绝对路径，禁止改写成 /data/local/tmp/a2a-files/ 或其它目录。
禁止编造路径；不要说配对/权限问题。
```

**为什么还要改 TOOLS：** 仅源码工具结果不够——模型会用 MEMORY 里的旧收件路径「纠正」话术。双轨才能压住改写。

### 3.3 设备 `TOOLS.md` / `MEMORY.md` 要点

**收件（唯一）**

| 设备 | 路径 |
|------|------|
| PC | `/storage/cloud/100/files/Docs/Download/OPENCLAW/` |
| Phone | `/storage/media/100/local/files/Docs/OPENCLAW/` |

**回报规则（新增硬约束）**

- 接收成功：原样完整复制消息里「保存路径」整行绝对路径  
- **禁止**改写成 `/data/local/tmp/a2a-files/` 或其它目录  
- 发本地文件：**不要传 `name`**；传输文件名 = path 的 basename

## 4. 运行时数据流（发送名 → 落盘名 → 聊天路径）

```text
用户 / Agent: a2a_send_local_file
  path = /.../IMG_realname_1724.txt
  name = "file.jpg"   ← 即使传入也被忽略
       │
       ▼
sendLocalFileCore
  wireName = basename(path) = IMG_realname_1724.txt
  FilePart = { name: wireName, mimeType, bytes }   ← 字段顺序见 2026-08-06 加固说明
       │
       ▼ 隧道 / 直连
对端 executor.formatFilePartAsText
  saveBase64File → fileStorage.tempDir / IMG_realname_1724.txt
  文案含：保存路径: /storage/.../OPENCLAW/IMG_realname_1724.txt
       │
       ▼
对端 Agent（读 TOOLS/MEMORY）
  聊天：接收成功 + 原样复制上述绝对路径
  （禁止改写成 /data/local/tmp/a2a-files/...）
```

```sh

```

| 设备 | 结果 |
|------|------|
| PC | 重启成功 |
| Phone（首轮） | **失败**：`Config invalid` — `plugin manifest not found: .../extensions/a2a-gateway/openclaw.plugin.json` |
